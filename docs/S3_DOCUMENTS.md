# TutorPair — S3 Document Strategy

> Covers how tutor verification documents and profile photos are stored, uploaded, and accessed securely using Amazon S3 Presigned URLs.

---

## Core Principle

The S3 bucket is **100% private**. No file is ever publicly accessible via a direct URL. All access — both uploads and downloads — goes through short-lived, signed URLs generated by the backend.

**The Express server never handles file binary data.** Files go directly from the browser to S3 (upload) or from S3 to the browser (download). The backend only handles metadata and URL generation.

---

## Bucket Structure (S3 Key Conventions)

```
tutorpair-documents/                         ← Private S3 bucket
├── profiles/
│   └── {userId}/
│       └── avatar-{uuid}.jpg               ← Tutor profile photo
└── tutors/
    └── {tutorId}/
        ├── cv-{uuid}.pdf                   ← CV / Resume
        ├── transcript-{uuid}.pdf           ← Academic transcript or graduation cert
        └── subject-proof/
            └── {variantId}-{uuid}.pdf      ← Subject qualification (e.g. IELTS cert)
```

**Key rules:**
- Every file gets a UUID suffix to prevent filename collisions and guessing.
- File keys are stored in the `documents.file_key` column in PostgreSQL.
- The bucket name is never hardcoded — always read from `env.S3_BUCKET_NAME`.

## Use Case 1: Tutor Uploading a Document (PUT Presigned URL)

**When this happens:**
- Tutor submits their CV, academic transcript, or subject qualification certificate.
- Tutor uploads a profile photo.

**Why not upload through Express?**
Loading a 10MB PDF through an ECS container means the container must hold the entire file in memory before forwarding it to S3. With multiple tutors uploading simultaneously, this causes Out-Of-Memory crashes on Fargate.

**Sequence:**

```
Tutor (Browser)              React App              Express (ECS)           Amazon S3
      │                          │                        │                     │
      │  1. Selects file         │                        │                     │
      │─────────────────────────▶│                        │                     │
      │                          │  2. POST               │                     │
      │                          │  /api/documents/       │                     │
      │                          │  presigned-upload      │                     │
      │                          │  { fileName, fileSizeKb, documentType,      │
      │                          │    variantId (optional) }                    │
      │                          │───────────────────────▶│                     │
      │                          │                        │  3. Validate:       │
      │                          │                        │  - Is user TUTOR?   │
      │                          │                        │  - fileSize ≤ 10MB? │
      │                          │                        │  - total ≤ 100MB?   │
      │                          │                        │  4. Generate S3 PUT │
      │                          │                        │  Presigned URL      │
      │                          │                        │────────────────────▶│
      │                          │                        │◀────────────────────│
      │                          │                        │  signed URL (10 min)│
      │                          │◀───────────────────────│                     │
      │                          │  { uploadUrl, fileKey }│                     │
      │                          │                        │                     │
      │                          │  5. PUT uploadUrl      │                     │
      │                          │  (raw binary file)     │                     │
      │                          │──────────────────────────────────────────── ▶│
      │                          │◀────────────────────────────────────────────│
      │                          │  200 OK                │                     │
      │                          │                        │                     │
      │                          │  6. POST               │                     │
      │                          │  /api/documents/confirm│                     │
      │                          │  { fileKey, documentType, fileSizeKb,       │
      │                          │    variantId }                               │
      │                          │───────────────────────▶│                     │
      │                          │                        │  7. INSERT INTO     │
      │                          │                        │  documents (...)    │
      │                          │◀───────────────────────│                     │
      │                          │  201 Created           │                     │
      │◀─────────────────────────│                        │                     │
      │  Upload complete ✓       │                        │                     │
```

**Backend endpoints involved:**
- `POST /api/documents/presigned-upload` → validates, returns `{ uploadUrl, fileKey }`
- `POST /api/documents/confirm` → stores metadata in PostgreSQL `documents` table

## Use Case 2: Admin Viewing Tutor Documents (GET Presigned URL)

**When this happens:**
- Admin opens the verification dashboard and clicks "View Transcript" or "View CV".

**Sequence:**

```
Admin (Browser)              React App              Express (ECS)           Amazon S3
      │                          │                        │                     │
      │  Clicks "View CV"        │                        │                     │
      │─────────────────────────▶│                        │                     │
      │                          │  GET                   │                     │
      │                          │  /api/admin/tutors/    │                     │
      │                          │  {id}/documents/       │                     │
      │                          │  {docId}/view-url      │                     │
      │                          │───────────────────────▶│                     │
      │                          │                        │  Verify ADMIN role  │
      │                          │                        │  Look up file_key   │
      │                          │                        │  from DB            │
      │                          │                        │  Generate S3 GET    │
      │                          │                        │  Presigned URL      │
      │                          │                        │  (expires: 15 min)  │
      │                          │                        │────────────────────▶│
      │                          │                        │◀────────────────────│
      │                          │◀───────────────────────│                     │
      │                          │  { viewUrl }           │                     │
      │  Opens viewUrl in        │                        │                     │
      │  new browser tab ────────────────────────────────────────────────────▶ │
      │◀─────────────────────────────────────────────────────────────────────  │
      │  PDF renders in browser  │                        │                     │
```

**After 15 minutes:** The presigned URL automatically expires. If the admin needs to view the file again, they must request a new URL. This is by design — it prevents link sharing.

## Use Case 3: Student Viewing Tutor CV on Profile

**When this happens:**
- Student views a tutor's profile from the Top 3 results and clicks to view the CV.
- This is only shown if the tutor has given consent (`consent_display_cv = true` — to be enforced in service logic).

**Sequence:** Same as Use Case 2 but:
- The endpoint is `GET /api/tutors/{tutorId}/cv-url`
- The middleware checks `requireRole(['STUDENT'])` instead of `['ADMIN']`
- The service checks that the tutor's `verification_status = 'APPROVED'` before generating the URL

---

## File Validation Rules (Enforced in `documents.service.ts`)

| Rule | Constraint |
|---|---|
| Maximum file size per document | 10 MB (10,240 KB) |
| Maximum total storage per tutor | 100 MB across all documents |
| Allowed MIME types | `application/pdf`, `image/jpeg`, `image/png` |
| File key format | Must use UUID suffix to prevent collisions |

These checks happen **before** the presigned URL is generated. If validation fails, the backend returns `400 Bad Request` and no S3 URL is issued.

---

## Document Types Reference

| `DocumentType` enum | When Required | `requires_proof` on variant |
|---|---|---|
| `CV` | All tutors — always required | N/A |
| `GRADUATION_CERTIFICATE` or `ACADEMIC_TRANSCRIPT` | One of these is required for all tutors | N/A |
| `SUBJECT_QUALIFICATION` | Only for subject variants where `requires_proof = true` in DB (e.g., JLPT N1, IELTS, SAT) | `true` |

The frontend dynamically shows/hides the subject proof upload field based on whether the selected `subject_variant.requires_proof` is `true`.

---

## Profile Photos

Profile photos follow the same presigned URL pattern but use the `profiles/{userId}/` prefix. Approved tutor profile photos may optionally be served via a public CloudFront distribution if needed in the future, but the initial implementation uses presigned GET URLs consistently.
