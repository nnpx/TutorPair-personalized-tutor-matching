# TutorPair — Database Guide

> Covers Drizzle ORM conventions, the migration workflow, schema organization, and rules all developers must follow when making database changes.

---

## Technology

- **ORM:** Drizzle ORM (TypeScript-first, no magic, SQL-like query builder)
- **Database:** PostgreSQL 16 (Amazon RDS in production, Docker container locally)
- **Migration tool:** `drizzle-kit`

---

## Schema Organization

Each table has its own schema file. All schema files are in `apps/server/src/db/schema/`.

```
db/
├── schema/
│   ├── users.schema.ts           # users table + UserRole, etc. enums
│   ├── students.schema.ts        # students table
│   ├── tutors.schema.ts          # tutors table
│   ├── subjects.schema.ts        # subjects + subject_variants tables
│   ├── availability.schema.ts    # availabilities table
│   ├── documents.schema.ts       # documents table
│   ├── matching.schema.ts        # match_requests + match_recommendations tables
│   ├── reviews.schema.ts         # reviews table
│   ├── notifications.schema.ts   # notifications table
│   └── index.ts                  # Barrel export: export * from all schema files
├── migrations/                   # Auto-generated SQL migration files (commit these to Git)
│   └── 0001_initial_schema.sql
├── client.ts                     # Creates and exports the Drizzle `db` instance
└── seed.ts                       # Seed script for local dev data (subjects, variants, test users)
```

## Migration Workflow (MANDATORY — Read Before Touching the Schema)

> **Never run `drizzle-kit push` on a shared local database or on production RDS. It can silently drop columns.**

### The correct workflow for all schema changes:

**Step 1 — Modify the schema file**

Edit the relevant `*.schema.ts` file with your table/column changes.

**Step 2 — Generate a migration file**

```bash
npm run db:generate
# This runs: drizzle-kit generate
# Creates a new SQL file in db/migrations/ (e.g., 0002_add_tutor_consent.sql)
```

**Step 3 — Inspect the generated SQL**

Open the new `.sql` file and verify it does exactly what you intended. Check that no `DROP COLUMN` or `DROP TABLE` appears unless you deliberately deleted something.

**Step 4 — Commit both files to Git**

```bash
git add apps/server/src/db/schema/tutors.schema.ts
git add apps/server/src/db/migrations/0002_add_tutor_consent.sql
git commit -m "db: add consent_display_cv column to tutors"
```

**Step 5 — Run the migration on your local database**

```bash
npm run db:migrate
# This runs: drizzle-kit migrate
# Applies all pending .sql files to your local PostgreSQL
```

On the next `npm run dev` startup, migrations run automatically to keep local databases in sync.

### Why this workflow?

When another developer pulls your commit, they run `npm run db:migrate` and their local database updates to match. Without migration files, their local database would be out of sync with the code, causing cryptic runtime SQL errors.

In production, migrations run as part of the ECS deployment process before the new container starts serving traffic.

## Drizzle Client Setup

The `db` instance is created once and exported from `db/client.ts`:

```typescript
// db/client.ts
import { drizzle } from 'drizzle-orm/node-postgres';
import { Pool } from 'pg';
import { env } from '../config/env';
import * as schema from './schema';

const pool = new Pool({ connectionString: env.DATABASE_URL });
export const db = drizzle(pool, { schema });
```

Import `db` in any repository file:

```typescript
// modules/students/students.repository.ts
import { db } from '../../db/client';
import { students } from '../../db/schema';

export const studentRepository = {
  findByUserId: (userId: string) =>
    db.select().from(students).where(eq(students.user_id, userId)).then(r => r[0] ?? null),
};
```

## PostgreSQL Enums

All PostgreSQL custom types (enums) are defined in the schema files using Drizzle's `pgEnum`. The TypeScript enum values are also exported from `packages/shared/src/enums/` so the frontend can use the same values.

**Rule:** If you add a new value to a PostgreSQL enum, you must:
1. Add it to the `pgEnum` in the schema file.
2. Add it to the corresponding TypeScript enum in `packages/shared/src/enums/`.
3. Generate a new migration (`npm run db:generate`) — adding an enum value requires an `ALTER TYPE` SQL statement.

## Naming Conventions

| Entity | Convention | Example |
|---|---|---|
| Table names | `snake_case`, plural | `match_recommendations` |
| Column names | `snake_case` | `hourly_rate`, `created_at` |
| Schema variable names | `camelCase` | `matchRecommendations` |
| Drizzle table export | singular, camelCase | `export const tutor = pgTable(...)` |
| Enum names | `PascalCase` | `verificationStatus` |
| Migration files | Auto-generated by `drizzle-kit` | `0001_initial_schema.sql` |

## Seeding Local Data

A seed script populates the database with subjects and subject_variants based on the predefined academic scope (Mathematics, IELTS, SAT, JLPT, etc.).

```bash
npm run db:seed
```

Always run the seed script after a fresh database setup. Without it, the subject cascade dropdown in the frontend will be empty.

---

## Local Database Setup (First Time)

```bash
# 1. Start PostgreSQL container
docker compose up -d

# 2. Apply all migrations
npm run db:migrate

# 3. Seed subjects and variants
npm run db:seed
```

Your local PostgreSQL will be available at `postgresql://postgres:password@localhost:5432/tutorpair`.

## npm Scripts Reference

| Script | Command Run | When to Use |
|---|---|---|
| `npm run db:generate` | `drizzle-kit generate` | After editing any schema file |
| `npm run db:migrate` | `drizzle-kit migrate` | After pulling new migration files from Git |
| `npm run db:seed` | `tsx db/seed.ts` | Fresh database setup, or to reset reference data |
| `npm run db:studio` | `drizzle-kit studio` | Opens a local Drizzle Studio GUI to browse data |
